### Updrades to be released in V3.0

- Component preservation: Added a gate requiring predicted and measured Xs to have the same component-presence pattern at every recovery slice; ensure that MC candidate PhysChem will generate eutectic cascade with recovery between the correct nodes (nb absense of this does not affect Rmax preduction in V1.0.x & V2.0.x)
- Components at or above 0.001% are treated as present.
- Recovery validity: Reject trial fits where predicted Rmax is above an observed recovery, allowing a small numerical tolerance.
- Slice weighting: Replaced the zero weight on the highest-recovery slice with positive linear weights from 0.50 to 1.00; tied recoveries receive equal weights.
- Python optimization: Select up to the best 10 gate-passing Monte Carlo candidates and apply the same gate during refinement. Run at least 1,000 trials, continuing up to 20,000 if needed; report shortfalls and fail explicitly if none pass.
- Parser: Reject single-component solid observations in both NODES and standard CRYSS files as “Rmax - 0% unconstrained”, including single-row mixtures. Retain other informative slices.
- QC reporting: Preserve rejected records in parser counts and summaries.
- Transition Stacked Plots to Plotly, allows saving of dynamic html objects with results for interrogation without the CRYSS app
- Include CRYSS-T: Topology surface and Gradient Radar plot for 'well mapped' systems.
